# CyberWolf 100-Day Cybersecurity Challenge

A guided daily challenge to build foundations, defensive thinking, practical confidence and a portfolio. Plan for roughly 45–90 minutes per day. Some tasks may take longer.

## How to complete
1. Read the day's objective and activity.
2. Practise on your own machine, a local lab, synthetic data or an approved training platform.
3. Record 3–5 learning notes and save safe evidence.
4. Mark progress in [progress-tracker.md](progress-tracker.md).
5. If you miss a day, resume without rushing or skipping foundations.

## The 100 daily activities

### Days 1–10: Foundations and networking
1. **Set your goal:** Write your current level, reason for learning and a realistic 100-day outcome.
2. **Explore cybersecurity roles:** Compare blue team, penetration testing, AppSec, cloud security, DFIR and GRC.
3. **Set up a learning journal:** Create folders for notes, lab reports and sanitized evidence.
4. **Authorization and scope:** Write five rules you will follow before any security assessment.
5. **Computer hardware:** Review CPU, RAM, storage, firmware and peripherals; draw a basic diagram.
6. **Operating system basics:** Explain processes, filesystems, users and services.
7. **Virtualization:** Learn VMs, snapshots and virtual networks; plan an isolated lab.
8. **Binary and hexadecimal:** Complete ten simple conversion exercises.
9. **Files and metadata:** Compare harmless sample file metadata, extensions and hashes.
10. **Review:** Summarize the first nine days and list your knowledge gaps.

### Days 11–20: Networking
11. **Network models:** Map common protocols to OSI and TCP/IP layers.
12. **Ethernet and MAC:** Draw how a host discovers a local neighbor.
13. **IPv4:** Create a subnetting cheat sheet for private lab ranges.
14. **Subnetting practice:** Solve ten beginner subnetting questions.
15. **IPv6:** Compare address notation and common address types.
16. **TCP and UDP:** Explain ports, handshakes and datagrams.
17. **DNS and DHCP:** Document a DNS resolution flow.
18. **HTTP and HTTPS:** Annotate a sample request and response.
19. **Routing and firewalls:** Draw a home network with trust boundaries.
20. **Network review:** Explain a DNS exchange in a packet-capture note generated from your own traffic.

### Days 21–30: Systems and scripting
21. **Linux navigation:** Practise paths, files and directories in a VM.
22. **Linux permissions:** Explain ownership and read/write/execute access.
23. **Linux processes:** Document how to inspect a service and process in your VM.
24. **Linux logs:** Summarize sample system and authentication log entries.
25. **Linux packages:** Write a safe update procedure for your lab VM.
26. **Windows accounts:** Create a fictional account and role matrix.
27. **Windows services:** Document the purpose of five common services.
28. **Event Viewer:** Explain event time, source and identifier.
29. **PowerShell:** Create a harmless system-information report.
30. **OS review:** Compare Linux and Windows administration and logging.

### Days 31–40: Programming and security
31. **Python fundamentals:** Write a small calculator or text-processing script.
32. **Files and exceptions:** Count lines in a sample file and handle errors.
33. **JSON and CSV:** Summarize a synthetic data file.
34. **Regular expressions:** Extract dates from sample text.
35. **Bash:** Write a script that counts files in a lab folder.
36. **Git:** Create a small repository with a useful README.
37. **JavaScript basics:** Explain client-side versus server-side responsibilities.
38. **Code quality:** Add validation, tests and clear error handling to a script.
39. **Scripting mini-project:** Build a parser for synthetic logs.
40. **Review:** Refactor one script and document its limitations.

### Days 41–50: Security fundamentals and defensive practice
41. **CIA triad:** Give two practical examples for each property.
42. **Threats and vulnerabilities:** Create a fictional threat-risk example.
43. **Risk assessment:** Create a five-item sample risk register.
44. **Least privilege:** Review a fictional access matrix.
45. **Authentication and MFA:** Create an account-security checklist.
46. **Hashing and encryption:** Hash sample files and explain the difference.
47. **Public key cryptography:** Draw a simplified signing flow.
48. **TLS and certificates:** Inspect certificate details for a website you visit.
49. **Security controls:** Map preventive, detective and corrective controls to a fictional risk.
50. **Review:** Write a security fundamentals summary.

### Days 51–60: Defensive security and web application security
51. **Logging:** Create a sample log-field dictionary.
52. **Authentication log analysis:** Identify anomalies in synthetic login events.
53. **Endpoint security:** Create a workstation hardening checklist.
54. **Network monitoring:** Analyze a benign capture generated by your own device or a training dataset.
55. **IDS/IPS:** Describe a detection idea and possible false positives.
56. **SIEM concepts:** Sketch a basic log collection and analysis pipeline.
57. **Incident response:** Create a response lifecycle flowchart.
58. **Threat intelligence:** Draft a fictional indicator-handling policy.
59. **Backup and recovery:** Create a backup verification checklist.
60. **Blue-team mini-project:** Publish a sanitized report for a synthetic suspicious-login scenario.

### Days 61–70: Authorized assessment and tools
61. **Rules of engagement:** Complete a scope template for a fictional lab.
62. **Reconnaissance concepts:** Compare passive and active discovery and their boundaries.
63. **DNS concepts:** Review a sample DNS dataset; do not enumerate unrelated targets.
64. **Nmap concepts:** Read official documentation and plan a scan against a local lab VM only.
65. **Lab service inventory:** Record services on an intentionally vulnerable local VM or authorized target.
66. **Vulnerability assessment:** Review a sample report and identify uncertainty and false positives.
67. **Safe validation:** Write a low-impact validation plan for a fictional finding.
68. **Reporting:** Draft an executive summary and technical finding.
69. **Remediation:** Write a retest checklist for a sample issue.
70. **Methodology review:** Write a complete mock assessment plan.

### Days 71–80: Web application security
71. **HTTP deep dive:** Annotate a request from a local demo application.
72. **Access control:** Threat-model role access in a fictional portal.
73. **Authentication security:** Review login, reset and session-management controls.
74. **Injection concepts:** Explain why parameterized queries reduce SQL injection risk.
75. **Cross-site scripting:** Complete a beginner PortSwigger lab or study a safe local example.
76. **CSRF:** Draw a threat scenario and document mitigations.
77. **SSRF and path traversal:** Review defensive URL-fetching and file-handling patterns.
78. **Security misconfiguration:** Audit a local demo app configuration.
79. **OWASP review:** Map three current OWASP risks to mitigations.
80. **Web security mini-project:** Fix one issue in a local intentionally vulnerable app and write regression tests.

### Days 81–90: Cloud, identity and incident response
81. **Cloud fundamentals:** Draw a shared-responsibility model.
82. **Cloud IAM:** Review a sample policy for excessive permissions.
83. **Cloud network security:** Sketch a secure sample network layout.
84. **Cloud storage:** Create a storage security review checklist.
85. **Containers:** Build and inspect a harmless sample container.
86. **Container security:** Review a sample Dockerfile for risks.
87. **Kubernetes:** Draw a cluster security boundary and identify RBAC roles.
88. **Identity lifecycle:** Create an access review checklist.
89. **Cloud mini-project:** Write a posture review for a sample architecture or sandbox.
90. **Forensics and incident response:** Create a mock evidence log and a synthetic event timeline.

### Days 91–100: Specialization and portfolio
91. **Timeline analysis:** Build a timeline from synthetic events and list unanswered questions.
92. **Incident tabletop:** Walk through a fictional account-compromise scenario without executing malware.
93. **Malware analysis safety:** Create an isolation and safe-handling checklist; do not run unknown samples.
94. **GRC and frameworks:** Map a fictional business objective to security controls.
95. **Choose a specialization:** Select a primary track and write a 90-day follow-up plan.
96. **Portfolio planning:** Define scope, deliverables, acceptance criteria and safety constraints.
97. **Build and validate:** Complete a project in a lab and capture sanitized evidence.
98. **Write the project report:** Document context, method, findings, fixes and limitations.
99. **Career preparation:** Write three evidence-based STAR stories from genuine learning work.
100. **Final review:** Record skills gained, gaps and your next-quarter learning plan.

## Safety rules
- Only test systems you own or have explicit written permission to assess.
- Use local virtual machines, synthetic data, CTFs and platform-authorized targets.
- Never scan or exploit third-party systems without authorization.
- Do not perform denial-of-service, destructive, stealth, persistence, credential theft or data-exfiltration activities.
- Keep credentials and personal information out of public evidence.

**Success is measured by understanding and evidence—not by speed or tool count.**
